## Why

TimeIndex 现有脚本主要验证模块能否运行，无法批量回答活动是否被正确记录、整理后是否更有用、能否找回目标记录，以及敏感信息实际保留在哪里。论文实验需要可重复的样本、自动评分和注明测量条件的结果，逐条人工检查成本过高。

## What Changes

- 在 `test_platform` 中新增本地网页和批量运行器，提供快速检查、完整实验和自定义样本入口。
- 用带标准答案的合成样本自动评价记录、摘要与标签整理、聚类和检索；在专用 Windows 测试电脑或虚拟机中自动打开真实软件并采集窗口与进程。
- 用虚构敏感串追踪采集、模型输入、摘要、存储与导出阶段的暴露情况，并检查现有屏蔽规则的实际效果。
- 将硬件资源测量设为默认关闭的可选实验，分别报告 TimeIndex 与本地模型服务的占用。
- 保存可复算的原始指标与失败案例，导出默认脱敏的论文用表格和 HTML 报告。
- 每次实验使用 TimeIndex 临时副本、独立配置和数据库；保留创建、运行、清理脚本。
- 2026-09-30 用户授权修复快速实验揭示的问题：修复 TimeIndex 整理写回丢失向量、空值转换、默认查询条数限制，以及提示词示例诱导和不完整整理响应处理；平台新增向量验收、同批评分和完整率检查。
- 2026-10-02 按用户要求贴合核心功能：仅评估可观察窗口/进程事实，自由标签按线索覆盖评估，整理批次沿用核心配置；增加独立真实软件模式和逐次接口请求/原始回复、软件实际启动与逐题返回证据。

## Capabilities

### New Capabilities

- `isolated-experiment-runs`: 批量实验的环境检查、独立运行、进度、取消及复现信息。
- `recording-evaluation`: 合成与真实桌面场景中的活动采集、漏记、重复和入库时延评价。
- `organization-evaluation`: 摘要事实、标签和重整理分组的规则评分。
- `recall-evaluation`: 对相同数据集进行语义、关键词和标签检索对照评价。
- `privacy-audit`: 虚构敏感信息的分阶段暴露审计与安全导出。
- `resource-profiling`: 可选的 TimeIndex、模型服务及磁盘和时延测量。
- `experiment-reporting`: 指标、失败案例、实验条件和可复算报告的保存与展示。

### Modified Capabilities

无。当前 OpenSpec 主规格目录为空，本变更不修改 TimeIndex 的对外接口。

## Impact

平台代码与规划文档位于 `test_platform`；2026-09-30 修复另涉及 `src/TimeIndex/db/vector_store.py` 和 `src/TimeIndex/daemon/llm_processor.py`。2026-10-02 不更改核心提示词或模型返回。实验读取源码并复制到独立目录，记录源码校验值。依赖 Windows、Python 3.12、现有 TimeIndex 依赖、本地网页组件，以及模型实验所需的 OpenAI 兼容本地服务；真实桌面要求专用测试电脑或 Windows 虚拟机。修复不迁移或修改已有生产数据库。
